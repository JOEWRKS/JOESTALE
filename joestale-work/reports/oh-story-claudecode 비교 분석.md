## 결론

선배가 아니라 다른 종류의 도구다. oh-story는 **중국 웹소설(起点·番茄·知乎盐言) 생산 파이프라인**이고(시장 스캔 → 인기작 해체 → 장편 연재 관리 → AI 티 제거 → 표지), JOESTALE은 **한 작가의 문장 원칙을 기계 검증과 사용자 피드백으로 고정하는 문장 수준 스킬**이다. 겹치는 부분은 deslop의 "表达" 층과 writing-craft §1(情绪落地)·§8(场景写法)뿐이다. 그 겹치는 부분에서 가져올 것이 셋, 가져오면 안 되는 것이 하나 있다.

## 겹치는 원칙 — 같은 결론에 이른 것

- 身体微动作은 감정의 기본 번역이 아니다. "指尖·指节·目光·嘴唇·呼吸 + 一下"가 반복되면 삭제, 부위 바꿔 돌려쓰지 말 것 → 패턴 26(수식어 간격)·연상 1회 규칙과 같다. 그들의 **삭제 테스트**("지우면 정보·선택·관계·물리 결과가 손실되는가")가 더 일반적이다.
- 否定铺垫后肯定翻转("不是 A 而是 B")은 "아무도 신경 안 쓰는 과녁을 먼저 부정"할 때만 결함, 교정·반박이면 유지 → 패턴 21(구체성 > 긍정/부정)과 일치.
- 深度限知: 시점 인물이 지금 보고 듣는 것만, "她不知道的是" 금지 → 패턴 36.
- 状态变化要给出台阶(시작과 끝만 주면 개요) → 패턴 34(행동과 결과의 간극).
- 开篇: 주인공 300자 내 압력 속에 등장, 날씨·풍경으로 시작 금지 → 패턴 28·22.
- 章尾 "就这样……/他终于明白……" 상태 요약 금지 → 패턴 24·20.

## 가져올 것 (추천 3 + 후보 2)

1. **검수 목록을 3층으로 재편하고 층별 처리 권한을 적는다.** 지금 38항목은 평면이다. oh-story는 表达(문장) / 用笔(詳略·장면 작용) / 故事(인과·지식·결과)로 나누고, 문장·용필은 직접 고치되 故事 층(사건·동기·결과 변경)은 작가 승인 뒤에만 고치게 한다. JOESTALE 패턴 1~32가 表达, 25·31·32·34가 用笔, 33·35~38이 故事에 해당한다. 검수 결과도 세 줄로 보고하게 하면 "스무스한데 감정 없음" 같은 판정이 어느 층 문제인지 바로 갈린다.
2. **한국어 AI 상투 템플릿 검사 T3.** 그들의 blocking 7종을 한국어로 옮기면 기계로 잡힌다: "~가 아니라 ~였다/~이었다"(부정 반전), "~도 없었다, ~도 없었다, 오직/다만"(부정 나열), "목소리는 크지 않았지만/낮았지만 ~"(음량 반차), "이제 시작이었다 / 아무도 몰랐다 / 그때는 알지 못했다"(예고 결말), 줄표 남용. 판정은 패턴 21대로 "과녁이 허수아비인가"를 검수자가 보되, 기계는 위치만 찍는다. 수락본 13편으로 오탐률 먼저 잰다.
3. **장편(round5 이후)용 추적 파일.** 연재를 하게 되면 chain.md 수기는 무너진다. 그들의 핵심인 **작가 진실 / 독자 기지 분리**와 伏笔 ID(심은 장·회수 장·상태)만 작게 가져온다. 패턴 36(인물 지식 범위)의 기계 검사 기반이 된다.
4. (후보) **가장 무거운 한 문장은 짧게, 단독 문단.** "长度表达绵延, 不表达重量" — 길이는 지속을 표현하지 무게를 표현하지 않는다. round4 결말 "할머니 몫 하나를 도로 놓았다"가 긴 문단 안에 묻혀 있는 것과 맞닿는다. 패턴 39 후보.
5. (후보, 사용자 판단) **R4(감정어 금지) 완화.** oh-story 입장: "一句'他很紧张'若准确、合乎声口且让下一步成立, 可以保留" — 정확하고 다음 행동을 성립시키면 직서 허용, 30자 연기로 돌아가지 말 것. 14차 피드백("여전히 감정은 없지만")과 패턴 38이 같은 방향이다. 다만 1원칙("감정을 말하지 말고 사물·행동으로")과 정면으로 부딪히므로 범위를 정해야 한다. 예: 저강도·경과 감정 1회 직서 허용, 결론 감정은 여전히 금지.

## 가져오면 안 되는 것

- short-craft의 腔调: 1인칭 피해자, 심사 판정구("那一刻我的心彻底死了"), 火葬场 예고, 100자 안에 사건 3개, 당중 모욕 — 상업 단편 공식이고 허관 원칙과 반대다.
- 450KB 참고 자료와 "EOF까지 읽기" 게이트. 그들 노트에도 호출당 35k 로드 상한을 두는 결정이 있다. JOESTALE은 작게 유지한다.
- lint 어휘 자체(중국어). 구조만 옮긴다.
- agents 7종·hooks·7호스트·대시보드. 문제가 아니라 규모가 다르다.

## JOESTALE이 갖고 그들이 없는 것

- 형태소 기반 수식어 비율·연상·감각 검사(R1~R8). 그들의 lint는 템플릿 문자열 매칭이다.
- 사용자 피드백 → 번호 패턴 → 검증기/검수자 반영 → 수락본 보존의 기록 루프(TASK/ISSUES/ROADMAP). 그들은 .agents/notes로 설계 결정을 남기지만 작가 취향은 author memory에 간다.
- 검증된 부정문 규칙(코퍼스 71/75 + 쌍 판정 12).
