# 문체·내용 분리 재검증 (T-061, 2026-11-15, 표본 8편·판정 112건 = Claude 48 + Codex Astra 48 + 웹 ChatGPT 16)

## 결론

Claude 평가자 셋(Sonnet 둘·Opus 하나), Codex Astra 셋, 그리고 사용자가 웹 ChatGPT에서 돌린 하나(모델명 미확인)가 같은 8쌍을 각 16판정씩 봤다. 웹 ChatGPT는 Astra와 종합·읽힘·설명감에서 한 건도 어긋나지 않았다(셈 없음 8:0, 문장형 읽힘 8:0). **OpenAI 넷과 Claude 셋이 일치하는 것 셋, 갈리는 것 하나.**

일치:
1. **문단 형태(한 줄형 vs 문장형)는 종합을 바꾸지 않는다.** 형태만 다른 쌍 56판정 중 52가 "둘 다 넘김"(Claude 24/24, OpenAI 28/32). T-060에서 문장형이 종합 24:0으로 이긴 것은 형태 때문이 아니었다.
2. **인물 셈 문장은 인물을 올리고 설명감·읽힘을 내린다.** 인물: Claude 16:0, OpenAI 16:4로 셈 있음 승. 설명감: Claude 0:24, OpenAI 0:32로 셈 있음 패. 읽힘: Claude 4:15, OpenAI 0:32로 셈 있음 패.
3. **같은 문장을 짚는다.** 좋은 셈으로 둘 다 "태석은 그 셈을 하고도 웃었다"를, 나쁜 셈으로 둘 다 이력 소개("이달 초에 제 손을 그렇게 감아 본 사람의 솜씨")와 독백 중복("장도 매주였다")을 들었다.

갈림:
- **셈 문장이 종합(다음 화 넘김)에 득인가.** Claude는 셈 있음 15:0, OpenAI 넷은 셈 없음 32:0. 당김도 Claude 11:0 대 OpenAI 0:26으로 정반대. 7명 합산 종합은 셈 없음 32 : 셈 있음 15이나 회사별로 완전히 갈리므로 합산은 뜻이 없다. GPT 셋은 "행동 뒤에 뜻을 거듭 풀이하면 다음 줄을 향한 당김이 약해진다", "사내의 의도를 단정하지 않을 때 더 불안했다"고 썼고, Claude 셋은 셈 문장이 "인물과 다음 장 긴장을 더 세게 남겼다"고 썼다. 형태 선호도 반대다(읽힘: Claude 한 줄형 16:8, OpenAI 문장형 32:0).

따라서 T-060의 "문장형 + 인물 셈 문장" 결론은 **평가 모델의 취향이 섞인 것**이었다. 모델 간에 재현된 것만 규범으로 삼는다. 셈 문장은 "인물을 사는 대가로 읽힘·설명감을 내는 다이얼"이고, 다음 화 넘김에 득이라는 증거는 없다.

여덟 번째 판 방향(교정):
- 형태는 변경의 죄수 기준점(1문장 60~70%) 그대로. 형태로 종합을 올릴 수 없으니 형태에 공을 들이지 않는다.
- 셈 문장은 장면당 **1~2개 이하**, 지금 지각·행동에 붙은 것만("그 셈을 하고도 웃었다"), 행동 문단의 끝 문장으로. 이력 소개·독백 중복·의도 단정("~를 재는 눈이었다"는 GPT 셋이 단정으로 짚음)은 쓰지 않는다. 그 이상은 플랫폼 독자 검수에서 "설명감"으로 돌아올 것으로 본다.
- 작가 비유 풀이 금지(T-060)는 유지.

## 설계

| | 내용 |
| --- | --- |
| 마스터 | T-060의 문장형(B)에서 작가 비유 풀이 3문장을 뺀 문장 집합. 외부 시점 문단(민규·노인)은 네 판 모두 같음 |
| 요인 | 형태 F1 한 줄형(서술 문장마다 문단, 1문장 100%, 서술 24~26자) / F2 문장형(마스터 문단 그대로, 1문장 37~50%, 서술 46~59자) × 내용 p 셈 있음(S1 5곳 7문장, S2 3곳 6문장) / m 셈 없음 |
| 표본 | 2장면 × 4 = 8편, 997~1,114자. 전부 check_text PASS. 생성은 `sep/gen.py`로 기계 변환(손으로 고치지 않음) |
| 쌍 | 장면마다 형태 효과 2쌍(F1p-F2p, F1m-F2m) + 내용 효과 2쌍(F2p-F2m, F1p-F1m) = 8쌍 |
| 평가 | Claude 3세션(Sonnet 5.5 둘, Opus 5.5 하나, fresh, pairs.md만 열람) + Codex Astra 3회(CLI 0.169, pairs.md만 든 격리 폴더, key 없음) + 웹 ChatGPT 1회(사용자가 pairs.md 첨부해 실행, 표를 붙여 줌, 모델명 미확인), 각 8쌍 × 순서 뒤집어 두 번 = 16판정, 총 112. 채점표는 T-060과 같음 |

파일: `joestale-work/profile-test/sep/` — `S{1,2}_master.txt`(⟦⟧ = 셈 문장), `gen.py`, 표본 `S{1,2}_F{1,2}{p,m}.txt`, `build_pack.py`, `tally.py`(평가자 번호 인자), `judge{1,2,3}/`(Claude), `judge{4,5,6}/`(Codex Astra), `judge7/`(웹 ChatGPT), `judge8/`(Gemini용, 미실행), `web_*_pairs.md`·`web_prompt.txt`(웹 실행용).

## T-060과 맞춰 보면

- T-060 B의 승리 요인 셋 중 "문단 형태"는 떨어진다. "인물 셈 문장"은 확인됐다. "작가 풀이 금지"는 이번 표본에서 뺐으니 재검증하지 않았으나 T-060에서 셋이 같은 문장을 짚었으므로 유지한다.
- T-060에서 대조군(일곱 번째 판)이 읽힘 1위였던 것과 이번 한 줄형 읽힘 16:8이 같은 말이다. 읽힘은 셈 문장이 없을수록, 줄바꿈이 잦을수록 오른다. 종합은 그것으로 움직이지 않는다.
- platform-norms "JOESTALE 적용"의 T-060 첫 줄("3인칭 서술은 문장형 프로필을 먼저 고려한다")은 이 결과로 고쳤다.

## 한계

- 회사는 둘(Anthropic·OpenAI)이다. 웹 ChatGPT가 Astra와 같은 방향이라 OpenAI 안에서는 모델이 달라도 일관되지만, 셋째 회사(Gemini)나 사람 독자 없이는 셈 문장의 종합 득실을 확정할 수 없다. Gemini용 묶음(judge8)은 만들어 두었다.
- 셈 문장의 "쓰는 것/쓰지 않는 것" 구분은 평가자 인용 문장에서 귀납한 것이고, 그 구분 자체를 다시 검증하지는 않았다.
- 단편 1,000자. 긴 문맥은 여덟 번째 판에서만.
